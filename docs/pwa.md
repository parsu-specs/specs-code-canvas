# Installing CodeCanvas

The saved palette, appearance, and scrollbar preference are restored by the parser-blocking `/startup-theme.js` before the head stylesheet and first paint, in both development and production. This is an external same-origin script, compatible with the deployed `script-src 'self'` policy. The initial splash is centered against `100vw`/`100dvh`, independent of document scrollbar gutters. Default scrollbar hiding is included in the head stylesheet rather than downloaded with JavaScript, preventing sideways movement during startup.

App icon artwork follows the favicon's resolved brand surface, foreground, and accent colors, including dark mode. Regular 192/512px PNGs have a 21.875% corner radius with transparent corners. Separate full-bleed Apple and maskable Android PNGs let each platform apply its launcher mask. Theme names are part of the public asset path, and the artwork version participates in the icon URL query so shape changes can invalidate earlier resources.

Production builds include `/manifest.webmanifest`, standalone display, a stable app ID, 192px and 512px icons, a separate maskable icon, an Apple touch icon, and matching launch colors. Serve the built site over HTTPS (localhost is suitable for development). Keep the manifest, worker, icons, launch images, and offline page publicly accessible without sign-in. Vercel configuration supplies the manifest MIME type and revalidation headers.

Settings > Install CodeCanvas offers the native install prompt when the browser supplies `beforeinstallprompt`. Otherwise it shows browser-menu instructions, including Safari's Share > Add to Home Screen on iPhone/iPad. Installed windows show their installed status. Prompt availability remains controlled by the browser.

Android builds its native splash from the manifest. Apple startup-image links cover common iPhone and iPad sizes in portrait and landscape. Other sizes fall back to the system launch experience. One theme-aware CC splash covers the initial HTML shell, fonts, session restoration, route download, and initial page data loaders. The stylesheet loads directly from the document head, and the CC is an inline vector with no image or font dependency. After the initial route commits and its LoadingRegions unmount, the splash fades directly into the page over 320 ms, with a 400 ms removal fallback. Reduced motion skips the fade. The page stays inert and hidden from assistive technology until reveal, and startup errors reveal recovery controls. Later navigation retains normal local skeletons without recreating the splash. There is no artificial minimum loading delay. The PNG assets use the two-toned CC monogram with the exact Fredoka outlines from `public/favicon.svg`; regenerate them on Windows with `powershell -File build/generatePwaAssets.ps1`.

The existing `/font-cache-worker.js` registration URL is preserved so existing installations upgrade in place. Registration only occurs in production secure contexts. Fonts retain their existing cache-first behavior. The worker also precaches a public offline page and its icon; document navigation stays network-only, falling back to that page on connection failure. API responses, account data, authenticated HTML, and app scripts are never cached. This is an offline connection notice, not full offline editing or catalog access. Increment `OFFLINE_CACHE` when changing its precached content. The worker activates immediately because it does not cache application code.

`src/utils/pwaBranding.ts` follows the existing appearance event, including palette/account changes and system dark mode. It updates the HTML theme-color to the resolved primary color for supported browser chrome and PWA title bars. Windows controls the outer resize border and system caption buttons; web code cannot force their color. The in-app splash follows CSS theme tokens and its inline CC graphic recolors directly through CSS.

The manifest is served by `api/pwa-manifest.js` at the stable `/manifest.webmanifest` URL. A public `cc_pwa_theme` cookie records only the device palette/mode, and `crossorigin="use-credentials"` allows manifest requests to send it. The endpoint validates the cookie against the 18 generated themes, returns private/no-store responses, and varies on Cookie. Vercel rewrites this URL to the function; Vite development and preview middleware use the same handler. Deploy the function along with the static build; a plain static-only host must supply an equivalent manifest endpoint.

Every theme has real, publicly fetchable icons and launch images under `/pwa/themes/<palette>-<mode>/`. Native app updaters can download them directly without a service worker or a visible app window. `build/generatePwaThemes.mjs` derives color metadata from the CSS tokens and authored dark palettes; the Windows asset generator refreshes the committed PNGs for all themes. The worker no longer intercepts manifests or themed artwork, and deletes the former branding cache on activation. Palette changes set the cookie before refreshing the manifest link; repeated identical theme events do not trigger another refresh. A worker upgrade also refreshes the link so an older cached manifest cannot remain selected.

The in-app splash, favicon, and supported theme-color chrome follow changes immediately. Installed icons and native launch screens remain browser/OS managed: updates may require approval, closing all app windows and reopening, or reinstalling on platforms such as iOS. The app supplies matching network assets but cannot force the OS to apply them instantly.

Verification: build the app, run `npm run preview` (which includes the manifest endpoint) or deploy to Vercel over HTTPS, and inspect Application > Manifest and Service Workers in Chrome/Edge DevTools. Change palettes and light/dark appearance; verify the theme-color meta value, touch icon, themed manifest colors, and PNG URLs. Install from Settings or the address bar, launch the installed app, verify standalone mode and splash, then switch offline and reload a deep route to verify the connection notice. Reconnect and select Try again to return to that route. Check Add to Home Screen and launch on physical iPhone/iPad; native installation, installed icon refresh, title-bar colors, and launch images require device verification.
