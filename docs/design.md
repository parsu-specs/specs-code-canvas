Design decisions

- Scrollbar visibility: Hide all scrollbar chrome and reserved gutters by default without changing overflow or scroll input. Settings > Experimental > Show scrollbars restores existing scrollbar styles. Keep this in `src/experiments/scrollbars`, initialize before React, persist per device under `cc.experimental.scrollbars.v1`, synchronize across tabs, and apply in memory when storage is unavailable. CSS hides scrollbars even before initialization.

- Feed project linking: Remove attachments with the labeled X beside the linked project in the composer, restoring focus to the link button. The picker only selects projects; omit a no-project option. Use the shared Modal fixedHeight mode (40rem capped at 90dvh), with stationary filters/search and an independently scrolling results area so filtering and loading do not resize the dialog.

- Modal surfaces: Use the palette-aware `bg-primary` with `text-primary-foreground` for modal headers and cream `bg-panel` for modal content and shells. Add the shared `modal-grid` utility to content areas for the same 36px paper grid as the page, using palette-aware paper-line colors without the red notebook margin; keep headers solid. Apply the same split to feedback, likes, Markdown viewer, centered selection, sign-out, and publishing dialogs. Preserve existing borders, scroll behavior, focus, dismissal, and dark-palette tokens.

- Feed layout: Keep the community composer, search, posts, and dialogs intact in the left panel. At 52rem of named content-container width, show featured apps and official announcements alongside it. Below that width, use a labeled 44px arrow button to switch between mounted panels so drafts and filters survive. Curated project IDs and official announcement content live in `src/data/feedHighlights.ts`; leave honest empty states until team content is supplied, and never infer official posts or substitute rankings. Resolve curated project IDs outside the initial catalog through the existing missing-project loader.

- Feed like and comment actions match the project view's content-fit controls, 14px count text, optical alignment, and 44px minimum height. Keep the heart with its voter count; feed comments continue opening in a dialog.

- Project-detail like counts match the adjacent comment control's 14px text and 44px interaction height. Offset both text labels down 1.4px with tight line height to optically align their glyphs with the icons; keep the controls and icons centered. Keep the heart and voter count together in one container, beside the comment control.

- Use "Collapse" for the control that reduces expanded comments or documentation.

- Project engagement shows the heart toggle, clickable like count, and clickable comment count in that order. Keep the heart icon-only with content-fit width and a 44px minimum height; comment activation scrolls to and focuses the feedback section below the fixed header.

- Additional screenshots sit immediately beneath the cover in a swipeable carousel with hidden scrollbars. Show one full-width, centered screenshot at a time, with center snapping, a position count, and 44px navigation buttons when multiple images exist. Clicking a screenshot opens the existing full-size viewer. Keep a single screenshot full-width without navigation controls.

- Project view starts with compact Back/Share navigation and a proportional 16:9 cover. Stack the preview and details on phones; use two columns only when the content area reaches 60rem. Let titles, version badges, and dates wrap, give Open app its own full-width mobile row, and group owner controls below the creator. Use tighter mobile section spacing and card padding, with matching loading placeholders.

- App-card icon-only actions stay circular with equal width and height and no flex shrinking. Like and share retain 44px mobile touch targets; text and count actions keep their content-sized shapes.

- Submission images use three matching 16:9 slots: a dashed clickable container opens the image picker, and an added image replaces an empty slot. Hide add controls naturally when all slots contain images; removing one restores a clickable slot. Keep multi-selection and sequential crop editing, and disable empty slots temporarily while editing, processing, or publishing.

- Sortable thumbnail previews fit all three images in one row at the submission modal's maximum width. Use fluid grid columns starting at 12rem, a 49.5rem maximum grid width, and a 16rem (256px) maximum tile width, with height following the 16:9 crop ratio. Reduce to two or one columns on narrow screens. Keep the cover badge, drag indicator, and remove action anchored to the image frame; omit left/right reorder arrows.

- Percentage inputs in the image editor use an inset `%` suffix in place of native up/down arrows. Preserve numeric typing, keyboard adjustments, and slider synchronization.

- Image editing: Show submission thumbnail crops inline at full available width with no preview padding, inset, or extra card frame. Round the preview corners with a clipping wrapper and overlay a 3px outline without changing canvas geometry; the overlay must let pointer gestures through. Circular avatar previews retain circular clipping. Users can drag, rotate, reset, or adjust zoom/position with sliders and percentage number fields. Number fields allow temporary empty drafts and normalize to valid slider bounds on blur. Process selected files sequentially, skip with Cancel, and disable publishing until edits finish. Accept browser-readable images plus iPhone HEIC/HEIF using an on-demand, on-device decoder; saved uploads use WebP with JPEG fallback. Animated uploads become still thumbnails.

- Mobile navigation: Below lg, use four bottom navigation destinations: Feeds, Discover, Developers, and Leaderboard, with compact 16px icons and 10px labels. Settings lives in the account popover and closes it when selected. Desktop retains its existing sidebar navigation and sizing, including Settings; do not duplicate Developers or Leaderboard in the mobile popover. Preserve touch target sizes, safe-area spacing, and active-route styling.

- Header account trigger: Show only a 28px avatar or fallback icon by default, with zero face padding. From md (768px), show the truncated account name beside a 20px avatar/fallback and restore the gap and 4px compact face padding. Both states have 28px of inner height, matching the adjacent appearance and notification controls. Use the secondary raised compact-icon button and preserve the accessible menu label and account-name tooltip. Responsive behavior uses default utilities with md overrides.

- Experimental font style: The shared Dropdown retains Default plus Elegant, Playful, Professional, Code, Editorial, Classic, Modern, Friendly, Academic, Retro, Minimal, and Creative. Give each preset a distinct heading face: Cormorant Garamond, Baloo 2, Barlow Condensed, Space Mono, Playfair Display, Libre Baskerville, Space Grotesk, Quicksand, IBM Plex Serif, Righteous, Inter, and Caveat, respectively. Pair these with readable contrasting body fonts and show the pairing below the control. Bundled Latin font files make condensed, rounded, geometric, serif, monospace, retro, and handwriting treatments available across devices. Only active families download. Choices apply immediately, persist on this device, and sync across tabs; Default restores the original typography.

- Auth hot updates preserve the shared context identity across provider and consumer modules. Inline trophy badges use spans for their wrapper and rank label, retaining their appearance inside author paragraphs.

- Crash recovery: Failed page downloads offer Refresh page. Other section crashes also offer only Refresh page, with an unsaved-changes notice. Session changes update the signed-in UI immediately; routine token refreshes preserve the current profile display.

- Mobile headers: Store uses a single fixed row for branding and theme/notification/account controls, with one two-tone CC text monogram by default and the full brand from md (768px). The sidebar starts at lg (1024px). Desktop retains the sidebar brand and theme control. Theme buttons match notification bell styling and sizing; public mobile headers place navigation on a separate row.

- Project submission uses a centered modal with a primary-colored header and cream content with a persistent title/close header and a scrollable responsive form. The dialog uses rounded corners to keep its close action and scroll area clear. Opening it locks background scrolling and interaction; backdrop clicks do not dismiss it. The close action or Escape opens a discard confirmation; Keep editing preserves the draft, while Close clears all fields, attachments, errors, and repository imports before dismissing and restoring keyboard focus. Closing is disabled during publishing. Only activating Publish project publishes after native validation; Enter in form fields never publishes. The description is a shared growing textarea with developer mention autocomplete and line breaks. Category selection uses the styled Dropdown above the modal, and Markdown documentation retains the shared MarkdownTextarea border, raised shadow, growth limit, and character count. Inner scroll areas use the shared `scrollbar-minimal` utility: a thin muted thumb, transparent track, and no arrow buttons. Collaborators appear once: selected developers are removable chips, while available developers are clickable rows without checkboxes.

- Page top spacing: Content starts 24px below navigation on mobile, 32px from sm, and 40px from lg. The store additionally clears its fixed 85px mobile header. Its shared heading-to-content gap appears only when a page heading exists, without extra route-section top margins. Home and About share this responsive top padding; sign-in remains vertically centered.

- Mobile-first Tailwind defaults and md overrides control dropdown presentation and scroll locking. Responsive popup copies share selection state and retain appropriate dialog semantics; no JavaScript device or viewport-breakpoint detection is used.

- Responsive dropdown triggers show icon plus selected label on larger devices (md / 768px and above), and icon only on mobile when mobileIcon is supplied.

- Mobile dropdowns: Below md (768px), styled Dropdown selections open in a centered, labeled dialog with a dim backdrop, scrollable options, 44px touch targets, close action, keyboard focus containment, and background scroll locking. Desktop selections remain anchored to their triggers. The optional mobileIcon prop hides trigger text and caret on mobile while preserving an accessible label and selected-value tooltip; the feed uses a project-link icon beside its count/send controls.

- Brand: The product is named **CodeCanvas**, a community platform for discovering and sharing digital creations, and an initiative by the Society of Programmers and Enthusiasts in Computer Science (SPECS). Use the reusable `src/components/Brand.tsx` lockup: the yellow stitched patch and lightbulb paired with the CodeCanvas wordmark.

- Tech: Vite + React + TypeScript for small, fast dev DX.
- Formatting: Prettier is the canonical formatter with project rules in `.prettierrc.json`. Use `npm run format` to write changes and `npm run format:check` for non-mutating validation; generated output, dependencies, lockfiles, coverage, and environment files are excluded through `.prettierignore`.
- Type declarations: Keep `src/vite-env.d.ts` with the standard `vite/client` reference so TypeScript recognizes CSS, static asset, and Vite environment imports without broad custom module declarations or relaxed compiler checks.
- Styling: Keep a restrained toon-like sketchbook treatment for an undergraduate computer science community. Define all palette and opacity colors in the `@theme` block in `src/styles/style.css`; use the softened ink, paper, violet, mustard, teal, and muted accent colors through theme utilities or CSS variables. Preserve hand-drawn paper details and outlines, but avoid candy-bright color combinations, oversized playful lettering, and excessive card framing.
- Style ownership: Shared card surfaces reference `toon-card` for borders, soft shadows, and wrapping, plus `toon-paper` for the clipped upper-right corner and tape. Both are defined in the components layer of `src/styles/style.css` so Tailwind utilities can override them. Components own layout, spacing, rounding overrides, background colors, cover stripes, stamps, underlines, and grid-child shrinking. Shared controls keep their classes inside Button/Input. Markdown styles its rendered elements locally and MarkdownTextarea owns its scrollbar variants; avoid global overrides beyond the shared card classes. Retain CSS for shared card styles, theme/animation definitions, runtime palette variables, the document canvas, native scrollbar defaults, and reduced-motion defaults. Put document sizing, fonts, and loading-dot utilities in the HTML/route loader; keep inline styles only for runtime data colors and measured geometry.
- Palette outlines: `--color-outline` follows ink in light palettes and uses dark gray in midnight. Use it for borders and hard control shadows so palette changes preserve contrast without overriding component hover/focus utilities.
- Background texture: The page canvas combines a 36px graph-paper grid, palette-controlled ink dots, and a pink notebook margin over the active paper background. It should read as working paper rather than a decorative dot pattern. Paint the texture on the root document canvas so natural elastic overscroll reveals the design, and repeat it on a fixed, non-interactive `body::before` layer extended beyond every viewport edge so vertical or horizontal pinch-zoom panning cannot expose a blank background. Keep the notebook margin aligned to the original viewport inside that oversized layer. Do not clip this canvas layer at `html` or `body`, and do not rely on `background-attachment: fixed`, which is unreliable on iOS WebKit. Clip accidental content overflow at `#root` and app-container boundaries instead, and allow the document roots to shrink below 320 CSS pixels when browser zoom reduces the effective viewport.
- Scrollbars: Use the defined navy `--ink` color for the track and corner, with the defined `--yellow` color for the rounded thumb and scrollbar buttons. Apply the treatment globally, including horizontal filter rails, with Firefox and WebKit-compatible rules.
- Typography: Self-host Latin Fredoka 700 and Nunito 400/700/900 through Fontsource, with four WOFF2 preload hints. Start authentication alongside the font requests. Main waits for those weights or a 1.5-second safety timeout before showing real page text, preserving typography while removing the session/font waterfall. Font failure never blocks startup.
- First-load performance and loading: bundle only the configured local, Supabase, or HTTP backend. Protected routes with a cached viewer hint start downloading the Store chunk directly from the HTML at low priority, ahead of the main entry executing; authentication still controls content and data access. Warm the catalog during font loading only after session restoration, reuse that request once for up to five seconds, and preserve one unfiltered browse/ranking fetch. Give the first catalog thumbnail and project cover high priority while the first desktop row remains eager. Background feed and notification reads wait 350 ms to let the first content paint.
- Stable controls: Reserve both compact and sidebar submission prompts while catalog data loads. Their alternate account-status copy shares overlapping slots so text wrapping does not move neighboring content. Keep a fixed desktop account-label slot and render the dismissed-prompt submission action disabled until projects are ready, preserving header height.
- Font caching: Register `public/font-cache-worker.js` after the page loads, including when the document has already finished loading before React mounts. It uses browser Cache Storage with a cache-first strategy only for requests whose destination is `font`, complementing Vite's content-hashed HTTP caching without affecting pages, scripts, styles, or API traffic. Change the cache version only if the caching policy itself changes.
- Icons: Use `@phosphor-icons/react` for interface and decorative icons. Prefer rounded `duotone` icons for playful visual moments and `bold` or `fill` for small actions and status marks. Keep icon sizes consistent within a control, pair unfamiliar icons with text, and use `aria-hidden` for decorative icons. Do not mix emoji or text glyphs into the interface icon language.
- Interaction: Primary interactive controls use Button's component-owned Tailwind classes and layered face/side elements. Preserve the raised hover/press travel, matching outline colors, visible keyboard focus, disabled states, and reduced-motion support.
- Action economy: Render a button or action link only when it performs a real, distinct operation. Avoid repeated calls to the same destination on one page and never show action affordances on static placeholder content. Responsive variants of the same essential action, such as sign-out, are allowed when they are never visible simultaneously.
- Layout and routes: `Main.tsx` renders public Home at `/` for both visitors and signed-in users; `/landing` and `/home` normalize to `/`. `PublicSite.tsx` shares the public header/navigation/footer between Home and `/about`. `/signin` provides authentication and resolves to `/discover` for signed-in users. `Store.tsx` owns protected `/discover`, `/developers`, `/developers/:username`, `/apps/:id`, `/feeds`, `/leaderboard`, `/profile`, and `/settings`; `/feed`, `/community`, and `/milestones` normalize to `/feeds`, and `/discover/:id` remains a legacy project path. Shared project/profile destinations survive sign-in. Profile paths use encoded display names; permanent mentions retain profile IDs. Keep route constants in `src/pages/routes.ts`. Mobile uses fixed top and bottom bars with matching content padding; at `lg`, restore the 280px sidebar and desktop breadcrumb together. Use `grid grid-cols-[repeat(auto-fit,minmax(min(100%,18rem),1fr))]` with targeted `min-w-0` on shrinkable card children so columns follow available container width, including the sidebar. Use shrinkable tracks and wrap long user text/actions.
- Shared controls: Use `Button`/`ButtonLink` for actions, `ButtonLabel` only for file input labels, and `Input`, `Select`, and `Textarea` from `src/components/Input.tsx` for text/form fields. Use `MarkdownTextarea` for growing Markdown editors and `Dropdown` for styled portal-based selection popups. `Button` forwards refs; `variant="plain"` supports bespoke cards, switches, menu options, and icon controls while preserving shared keyboard focus and disabled states. Prefer existing visual variants for standard actions. Use shared `FileInput` and `Checkbox` controls from `Input.tsx`; they retain native browser semantics without text-field styling. Keep medal/trophy colors in the CSS theme.
- Markdown files: Scope Markdown file actions to project submission and a specific project's documentation; do not show a global catalog viewer button. During submission, allow manually writing/uploading docs or listing public GitHub repository Markdown files and selecting individual files or all files; show the repository option only for a recognized GitHub repository URL. Provide a Preview/Edit toggle aligned to the upper right of the writing, upload, and repository controls, and in project editing. Markdown writing fields auto-grow to fit their content, cap at 60vh/32rem, and show an inset scrollbar after reaching the cap while retaining the shared raised input shadow. If combined selected content exceeds 50,000 characters, show a warning and allow downloading the full Markdown, but block publishing until shortened to fit the project storage limit. Allow repository files up to 200KB each for preview/download; the combined project documentation remains limited to 50,000 characters for publishing. The project documentation section provides a download of the currently displayed Markdown. Project documentation prefers submitted custom docs; when absent, public GitHub repository URLs fall back to the repository README. Render both sources with the safe `react-markdown` + GFM renderer and sketchbook styles, rejecting binary/media input.
- Performance: Keep dependencies minimal; use React 18, strict typing, and avoid heavy libraries.
- Accessibility: Use semantic controls, contrast, and focus outlines. Allow native viewport pinch zoom, trackpad pinch, browser menu, keyboard, and Ctrl+wheel zoom without a settings toggle or magnification-reset workaround. Keep touch restrictions scoped to interactive image/drag surfaces that own those gestures. The store header stays fixed alongside the sidebar with content padding to clear it.
- Documentation: Every implementation change must include a review and, when relevant, an update of both `design.md` and `agent.md` so the documented design stays aligned with the application.

- Documentation structure: `README.md` is the project entry point; `docs/README.md` indexes setup, architecture, backend contracts, operations, and UI audit notes. Keep `design.md` and `agent.md` at the root. The PDF is a historical snapshot, not maintained documentation.

- App card sizing: Discovery and profile project cards retain the 24rem width cap and 32rem height. Discovery uses auto-fill grid tracks with an 18rem minimum and 24px gaps. Center cards when only one column fits; left-align multi-column rows, including an incomplete last row. Center a lone filtered result at any width. Skeleton cards use the same grid.
- Browse headers: Show one concise page title and a compact submission action. Omit decorative header stamps and repeated catalog/developer/feed headings; show supporting header text from `sm` upward. Discovery flows from any account notice to search, compact category filters, and project results. Keep search adjacent to the content it filters and avoid a second first-project submission prompt.
- Paper corners: All matching paper surfaces use the original clipped upper-right silhouette, defined by the shared `toon-paper` class in `src/styles/style.css` (36px corner cut, 5px allowance around the other edges). Keep the tape and shadows consistent across cards, forms, notices, profile/project panels, empty/error states, and the Markdown viewer.

- Markdown fade: Project documentation cards explicitly use `bg-surface`; `PagedMarkdown` defaults its fade gradient to `var(--color-surface)` so the fade matches the card across palettes. Override `fadeTo` when embedding on another background.

- Component reuse: Standard calls to action, including ?Submit your first project,? use the primary/secondary/surface Button variants instead of `plain` with duplicated button styling. Reuse `icon`, `menu`, `text`, and `filter` variants for common controls; reserve `plain` for bespoke compositions. Navigation and action anchors use `ButtonLink`. File chooser labels expose focus through `ButtonLabel`; file and checkbox elements are centralized in `Input.tsx`. Keep native buttons, anchors, text/select/textarea fields, file inputs, and checkboxes inside their shared primitives rather than repeating them in page/view code. Semantic layout elements and Markdown renderer output remain appropriate native HTML.

- Responsive sizing: Use targeted `min-w-0` on flex/grid children that need to shrink for long text. Avoid blanket child sizing utilities, redundant `max-w-full` on full-width elements, and repeated `toon-card` defaults. Wrap action rows and long text; constrain controls with `max-w-full`. Nested two-column forms use the named `content` container at 36rem, including matching column spans. Preserve adaptive card grids and the 24rem app-card cap. Keep controls and focus indicators clear of the clipped paper corner; avoid rotating discovery cards. Dropdown restores the original styled portal popup with viewport-aware placement, keyboard navigation, Escape/outside dismissal, and focus return. Its default is the original checked single-select; explicit variants are `default` (plain), `icons` (option icons), `check` (selected checkmark), and `checkbox` (multiple selections using the shared Checkbox). Reuse Button for triggers/options and Input styling for the trigger; keep native Select for ordinary form fields. Textarea and MarkdownTextarea share native `field-sizing: content`, with manual vertical resizing in unsupported browsers. MarkdownTextarea delegates sizing to Textarea, reserves three lines plus padding, keeps a stable scrollbar gutter, and wraps long lines. Both retain the dynamic viewport height cap and internal scrolling. PagedMarkdown observes an unclipped inner wrapper independently of the visible height, preserving stepped reveal without hiding the final 24px. Keep the oversized canvas layer for zoom/overscroll coverage and keep actual bitmap upload resizing.

- Textarea footers: Textarea accepts children inside the bottom of its shared field frame. Use a child render function receiving the character counter to place it beside actions; enable the counter with showCharacterCount and maxLength. Use an external label with htmlFor when including interactive footer controls. The feed composer keeps its project dropdown and Post action in this footer, with the count immediately left of the send icon button. The send action uses a Phosphor PaperPlaneTilt icon, an accessible Send update label, and a busy state while submitting. Minimal buttons use a pointer cursor when enabled and have no hover or press effects; disabled send buttons use muted gray and the default cursor while retaining keyboard focus indicators when enabled. Button and native Select support the minimal variant; Dropdown uses triggerVariant=minimal for the same borderless, shadow-free treatment while preserving popup selection behavior and keyboard focus.
- Viewer persistence: AuthProvider owns the current profile across all routes, showing validated cached public profile fields after session verification and refreshing through the repository in the background. Profile edits update that cache immediately. Cache sign-in-method display state and password-nudge state to avoid settings placeholders, without treating cached data as authorization. Scope profile and appearance caches by backend and account; visitors use the default Candy palette with independently saved light/dark/system appearance. The entry point eagerly applies the saved palette and mode before mounting on Landing, About, and Store. Migrate legacy device palette/appearance only once after verified sign-in. Keep cached profile data on refresh failures; clear the active viewer on sign-out or invalid sessions.

- Image viewing: Project screenshots and About photos use the shared `ImageViewer` inside `Modal`, retaining its sky surface, rounded outline, persistent header, background lock, focus containment, and focus return. Close with X or Escape; backdrop clicks keep the viewer open. Keep the image area black across palettes with hidden scrollbars. Offer fit, 150%, and 200% image zoom with internal scrolling and pointer-captured mouse/touch/pen dragging while zoomed; release dragging on pointer up, cancellation, lost capture, or view reset; project galleries also have bounded previous/next controls, image counts, and Left/Right keyboard navigation. Navigation resets zoom and scroll. Keep error messages inside the preview and disable zoom when an image fails.

- About page: Lead with CodeCanvas as the product identity and the tagline "A home for what you build." Use a split introduction and purpose note, supported-creation lists shared with Home, three concise feature summaries, team cards with photo viewing, and a compact email contact panel. Include a secondary organization section naming the Society of Programmers and Enthusiasts in Computer Science (SPECS) as the organization behind the initiative, with public/specs-logo.png. Keep its logo outside the hero and student/alumni roots in this background context. Shared copy, creation types, and organization details live in src/data/team.ts; follow docs/branding.md.

Dismissal replaces the prompt with a submission action beside the Discover heading using space-between: an accessible plus-only button below lg and a labeled button on desktop. Canceling the modal retains the prompt; confirmed dismissal focuses the replacement action. Keep the sidebar vertically scrollable on short screens.

A sketched jack-o-lantern, wrapped sweet, crescent, ghost, bat, and small stars use rounded strokes and dashed ground marks to match the app sketchbook aesthetic. Place most detail at the bottom and outer edges, behind navigation, with no extra layout height or glow.
- Halloween graph paper: Scatter sparse outlined seasonal doodles through the main canvas as a repeating printed ink texture. Keep the graph grid and notebook margin visible, use the current palette ink at low opacity, and reduce the tile size on mobile. Artwork stays behind content and does not create a foreground overlay or change layout.
